# Part A - Theory 
### **1. Nine Pillars Understanding**

**Why is using AI Development Agents (like Gemini CLI) for repetitive setup tasks better for your growth as a system architect?**

Since agents handle the repetitive tasks, we as system architects can focus more on designing systems, planning workflows, and making strategic decisions. This prevents us from wasting time on routine setup work and helps us practice real architecture thinking.

**Explain how the Nine Pillars of AIDD help a developer grow into an M-Shaped Developer.**

The Nine Pillars create a complete system (TDD, SDD, agents, MCP, etc) that exposes a developer to multiple areas of development. Working with these tools helps build deep skills in several domains instead of just one, turning a developer into an M-shaped professional rather than a simple T-shaped one.

---

### **2. Vibe Coding vs Specification-Driven Development**

**Why does Vibe Coding usually create problems after one week?**

Without planning or structure, the code quickly becomes messy and hard to extend or debug. As the project grows, the lack of clear direction makes everything harder to manage and can even cause the whole system to fail.

**How would Specification-Driven Development prevent those problems?**

SDD starts with clear written specifications about what the code must do. This removes confusion, reduces bugs, and makes the project easier to maintain, extend, and test as it grows.

---

### **3. Architecture Thinking**

**How does architecture-first thinking change the role of a developer in AIDD?**

With architecture-first thinking, a developer acts more like a system designer rather than just someone writing code. Instead of manually typing everything, the developer guides AI tools like an architect, focusing on structure and intent.

**Explain why developers must think in layers and systems instead of raw code.**

Modern applications are complex and need proper structure (UI, logic, data, agent etc) layers to scale properly. Thinking in layers keeps the system organized and manageable, while raw code alone becomes chaotic and hard to maintain.
